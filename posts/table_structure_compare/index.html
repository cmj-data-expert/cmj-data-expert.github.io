T-SQL for Comparing Backup and Original Table Structures

October 18, 2026 · 4 min · 769 words · Me |  Suggest Changes

테이블 구조 비교 스크립트 (원천 vs 백업)#

1. 개요#

같은 스키마 안에 있는 원천 테이블과 그 백업 테이블(_BU 접미사) 의 컬럼 구조를 비교하는 SQL Server 스크립트입니다. 어떤 테이블의 어떤 컬럼이 어느 항목에서 다른지를 한 번에 확인할 수 있도록 결과를 임시 테이블에 정리합니다.

  • 대상 DBMS : SQL Server 2017 이상
  • 원본 : Oracle 익명 블록 기반 스크립트를 SQL Server용으로 변환·확장한 버전
  • 데이터 변경 : 없음 (조회 전용, 모든 작업은 세션 임시 테이블에서만 수행)

2. 사용 목적#

  • 백업 테이블 생성 후 원천과 구조가 동일한지 검증
  • 원천 테이블 구조 변경(컬럼 추가·타입 변경 등) 후 백업과의 차이 파악
  • 한쪽에만 존재하는 테이블(백업 누락, 불필요한 백업) 식별

3. 비교 대상 정의#

구분대상식별 방법
원천지정 스키마의 일반 테이블테이블명이 _BU로 끝나지 않는 테이블
백업지정 스키마의 백업 테이블테이블명이 _BU로 끝나는 테이블
매칭원천 ↔ 백업백업 테이블명 끝의 _BU 3자리를 제거한 이름 = 원천 테이블명

뷰(View)는 비교 대상에서 제외되며, 실제 테이블(BASE TABLE)만 비교합니다.

4. 비교 항목#

컬럼명이 같은 컬럼끼리 아래 7개 항목을 비교합니다. (번호는 결과 표기 순서)

순번항목명 (NOSM_NM)비교 내용
1데이터유형명데이터 타입 (VARCHAR, NUMERIC 등)
2길이VARCHAR 최대 길이 / NUMERIC·DECIMAL 정밀도
3소수점NUMERIC·DECIMAL 소수 자릿수
4PK여부기본키 구성 컬럼 여부 (Y/N)
5NULL여부NULL 허용 여부 (Y/N)
6컬럼순서테이블 내 컬럼 위치
7디폴트값컬럼 기본값

비교 시 정규화 규칙#

비교 전에 값을 아래와 같이 맞춘 뒤 비교합니다.

  • 데이터 타입 : 대문자로 통일
  • 길이 : VARCHAR, NUMERIC/DECIMAL 외 타입은 비교하지 않음(NULL 처리)
  • 소수점 : 값이 없으면 0으로 간주
  • PK여부 : 값이 없으면 N으로 간주
  • NULL여부 : YES/NO → Y/N 형식으로 변환
  • 컬럼순서 : 백업 테이블의 컬럼 순서는 1을 뺀 값으로 보정 후 비교 (백업 테이블 앞쪽에 컬럼이 1개 더 있는 구조를 전제로 함)
  • 디폴트값 : 앞뒤 공백 제거 후, 값이 없거나 빈 문자열이면 xxx로 치환하여 비교

5. 처리 흐름#

단계내용결과 임시 테이블
0이전 실행에서 남은 임시 테이블 정리-
1백업 DB의 컬럼 메타정보 수집 후 _BU 테이블만 남김#T$NUC_DB_TBL_M_TEMP
2원천 DB의 컬럼 메타정보 수집 후 _BU 테이블 제외#T$NUC_DB_TBL_M
3짝이 되는 백업이 없는 원천 전용 테이블 추출#T$PD_ONLY
4짝이 되는 원천이 없는 백업 전용 테이블 추출#T$SI_ONLY
5원천 테이블별 PK 컬럼 목록 (컬럼 순서대로 콤마 연결)#T$PD_PK_INFO
6백업 테이블별 PK 컬럼 목록#T$SI_PK_INFO
7비교 기준(항목·순번) 참고 조회(조회만)
8원천·백업 컬럼을 매칭해 항목별 불일치를 모두 찾고, 컬럼 단위로 묶어 정리#T$NOSM_TEMP
9최종 결과 조회 (이력 테이블 적재용 형식)(조회 결과)

8단계 핵심 동작#

  1. 원천과 백업을 테이블명(접미사 제거) + 컬럼명으로 매칭합니다.
  2. 매칭된 컬럼마다 7개 비교 항목을 각각 비교합니다.
  3. 불일치한 항목만 골라 컬럼 1건당 1행으로 묶습니다.
  4. 불일치 항목명과 양쪽 값을 항목 순번 순서로 콤마(,) 연결합니다.

→ 한 컬럼에 여러 항목이 동시에 다르더라도 모든 불일치 항목이 한 행에 표시됩니다.

6. 결과 컬럼 설명 (9단계)#

컬럼설명
NOSM_SNO결과 일련번호 (테이블명·컬럼순서 기준)
OWNER스키마명
TABLE_NAME / COLUMN_NAME원천 테이블명 / 컬럼명
CMP_OWNER비교 대상 스키마 (미사용, NULL)
CMP_TABLE_NAME / CMP_COLUMN_NAME백업 테이블명 / 컬럼명
JOIN_TP_CD매칭 구분 (JOIN 고정)
NOSM_NM불일치 항목명 목록 (콤마 구분)
VAL1원천 값 목록 (NOSM_NM과 같은 순서)
VAL2백업 값 목록 (NOSM_NM과 같은 순서)
PK_COL_INFO불일치 항목에 PK여부가 있을 때만 원천 테이블의 전체 PK 컬럼 목록
CMP_PK_COL_INFO위와 같은 조건에서 백업 테이블의 전체 PK 컬럼 목록

결과 예시#

TABLE_NAMECOLUMN_NAMECMP_TABLE_NAMENOSM_NMVAL1VAL2PK_COL_INFOCMP_PK_COL_INFO
ORDER_MORDER_NOORDER_M_BUPK여부YNORDER_NO
ORDER_MCUST_NMORDER_M_BU길이,NULL여부100,N50,Y
ORDER_DQTYORDER_D_BU데이터유형명,길이,소수점NUMERIC,10,2VARCHAR,20,0

값은 이해를 돕기 위한 예시입니다. VAL1·VAL2는 NOSM_NM의 n번째 항목과 n번째 값이 서로 대응합니다.

7. 사용 방법#

  1. 스키마명 설정 : 스크립트 안의 스키마명(기본값 dbo)을 비교할 스키마로 변경합니다.
  2. 원천 DB 지정 : 원천 메타정보 수집 단계의 DB명을 실제 원천 DB로 지정합니다.
    • 같은 인스턴스 : [DB명] 형태
    • 다른 서버 : [링크드서버명].[DB명] 형태
  3. 한 세션에서 전체 실행 : 로컬 임시 테이블(#)은 세션이 끊기면 사라지므로, 하나의 쿼리 창에서 처음부터 끝까지 실행합니다.
  4. 결과 확인
    • 구조 불일치 : 9단계 조회 결과 (또는 #T$NOSM_TEMP)
    • 원천에만 있는 테이블 : #T$PD_ONLY
    • 백업에만 있는 테이블 : #T$SI_ONLY

필요 권한#

  • 대상 DB의 메타데이터(테이블·컬럼·제약조건 정보) 조회 권한
  • tempdb 임시 테이블 생성 권한 (일반 사용자 기본 보유)

8. 유의사항 및 한계#

  • 컬럼명이 같은 컬럼끼리만 비교합니다. 컬럼명이 바뀐 경우나 한쪽에만 있는 컬럼은 불일치 결과에 나오지 않습니다. 이런 경우는 결과적으로 컬럼순서 불일치로 간접 확인될 수 있습니다.
  • 한쪽 값이 NULL이면 불일치로 잡지 않습니다. (예: 길이 NULL vs 10) 데이터 타입이 다른 경우는 데이터유형명 항목에서 먼저 확인됩니다.
  • 길이 비교 대상은 VARCHAR, NUMERIC/DECIMAL뿐입니다. NVARCHAR, CHAR 등은 길이를 비교하지 않습니다.
  • 컬럼순서는 백업 쪽에 -1 보정을 적용합니다. 백업 테이블 구조가 이 전제와 다르면 모든 컬럼이 컬럼순서 불일치로 표시될 수 있습니다. 이때 VAL2에는 보정된 값이 표시됩니다.
  • 디폴트값에 콤마가 포함되면 VAL1·VAL2에서 값의 경계가 헷갈릴 수 있습니다.
  • 테이블명 끝이 _BU인 테이블은 모두 백업으로 간주합니다. 업무 테이블 중 _BU로 끝나는 이름이 있다면 원천 비교에서 빠지므로 주의합니다.
  • 원천·백업은 같은 스키마 기준으로 매칭합니다.
